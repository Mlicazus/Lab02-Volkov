## Результаты замера Debug vs Release
| Режим      | Запуск 1 |  Запуск 2 |  Запуск 3 |  Запуск 4 |  Запуск 5 |  Минимум |
| Debug      | 3848 мс  |  3563 мс  |  3684 мс  |  3719 мс  |  3540 мс  |  3540 мс |
| Release    | 451 мс   |  583 мс   |  462 мс   |  635 мс   |  390 мс   |  390 мс  |

В моём эксперименте Release оказался быстрее Debug примерно в 7 раза.

Что я обнаружил при сравнении IL

1. В Add, который находится в Release примерно в 2 раза меньше промежуточных операций, нежели в том, который находится в Debug
2. В Debug_Add 10 IL-инструкций, в то время как в Release_Add всего 4  IL-инструкций.

## Ответы на контрольные вопросы

1. Это промежуточный код, который хранит в себе информацию о типах, методах, классах и др элементах программы.

2. Потому что он содержит IL и метаданные.

3. В Debug намного больше промежуточных операций и IL-инструкций, нежели в Release.

4. Потому что компилятор в Release устранил часть промежуточных операций с локальной переменной и стало в 2 раза меньше IL-инструкций.

5. Потому что .dll легко можно декомпилировать в код, который будет похож на исходный, тем самым любой человек можно с легкостью узнать пароли.
